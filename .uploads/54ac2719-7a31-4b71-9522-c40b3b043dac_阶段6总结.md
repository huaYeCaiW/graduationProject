## 二、阶段 6 的交付内容

目标：给所有查询接口加租户数据过滤，并补齐登录鉴权。

### 2.1 接口清单

| 接口 | 说明 | 租户行为 |
|---|---|---|
| `POST /api/auth/login` | BCrypt 校验 + Session | — |
| `GET /api/auth/me` | 当前会话用户 | — |
| `POST /api/auth/logout` | 销毁会话 | — |
| `GET /api/devices` | 设备列表 | 按 `device.tenant_id` 过滤 |
| `GET /api/devices/{deviceCode}` | 设备详情 | 越权 / 不存在均 404 |
| `GET /api/points/{deviceCode}/{pointCode}/latest` | 最新值 | 越权 404 |
| `GET /api/points/{deviceCode}/{pointCode}/range` | 区间历史 | 越权返回 `[]`（200） |
| `PUT /api/points/{deviceCode}/{pointCode}/threshold` | 改阈值 | 越权 404 |
| `GET /api/alarms` | 全部告警 | join point→device 过滤 |
| `GET /api/alarms/active` | 活跃告警 | 同上 |
| `POST /api/alarms/{id}/confirm` | 确认告警 | 拦截器限 OPS/ADMIN |
| `GET /api/snapshots` | 内存快照 | 按设备归属过滤 |

### 2.2 分层约定（四条链路统一）

```
Controller   身份解析、HTTP 状态码（@RequestAttribute LoginUser）
    ↓
Service      LoginUser → TenantScope.of(user) 的唯一转换点
    ↓
Store 接口   查询方法统一带 TenantScope
    ↓
Jdbc 实现    seeAll 走原语句；否则拼 tenant_id 条件
```

- `TenantScope` 是 record：`(boolean seeAll, Long tenantId)`，`canSee(Long rowTenantId)`
- `seeAll = role == ADMIN || role == OPS`；平台判定必须绑角色，不能用 `tenantId == null`
- 未归属 FARMER（`tenant_id` 为 null）→ 空集，靠 SQL `= null` 恒 false 兜底
- SQL 禁止 `or ? is null`（会导致索引失效），坚持双分支拼串
- 采集链路（`save` / `insert` / `touch` / `markRecovered` / `findAllActive`）永远全量，不经过 scope
- 越权与不存在统一 404；集合查询空结果返回 200 + 空集合；401/403 由拦截器负责

### 2.3 Snapshot 的特殊性

`snapshot` 没有 SQL 可下推，只能内存过滤：

- 数据源是 `ConcurrentHashMap`，迭代器弱一致，无需加锁也不会抛 `ConcurrentModificationException`
- `seeAll` 分支返回 `Map.copyOf` 的不可变副本，其余分支边遍历边收集到 `HashMap`
- 设备归属通过 `DeviceProperties.findDevice(code)` 反查，用 `map(...).orElse(false)` 兜住"设备已删"的情况
- 写入侧 `snapshot(pv)` 不带 scope，`MessageStream` 只调这一个方法

### 数据库（原地修复，非脚本入库）

`device.name`、`point.name`、`point.unit`、`tenant.name`、`tenant.contact` 存在双重编码，已用下述模式原地解码：

```sql
update point set name = convert(cast(convert(name using latin1) as binary) using utf8mb4);
```

修复后验证：`point.name` = `E6B8A9E5BAA6`（温度），`unit` = `E28483`（℃），`device.name` 为完整中文传感器名。

> 注意：该语句**不可重复执行**，第二次会把正常中文再次破坏；执行完必须重启应用，让 `DeviceProperties` 重新加载。

## 四、关键设计决策

| 决策 | 选择 | 理由 | 代价 |
|---|---|---|---|
| 过滤位置 | Store / Jdbc 层 | 规则只写一次，四条链路一致；避免 Service 里 N 份重复 | Store 接口签名全部要带 scope |
| 越权返回 | 404 | 不泄露资源存在性 | 排障时难区分"没权限"与"不存在" |
| 集合空结果 | 200 + 空集合 | 空是正常状态，404 会让前端把"没数据"当故障 | 前端需自己判断空集合 |
| Snapshot 过滤 | 内存里做 | 无 SQL 可下推 | 依赖 `DeviceProperties` 快照，库改设备后需重载 |
| 全量 vs 过滤 | `seeAll` 短路 | 平台角色不必白白拼 join | 两条 SQL 分支要各自维护 |
| `Map.copyOf` | 仅 `seeAll` 分支 | 防外部改写内部 map；普通分支是新容器，无需再拷 | 平台请求多一次 O(n) 拷贝 |

### 5.1 回归脚本

位置：`d:\Learn\GraduationProject\api-regression.ps1`

```powershell
powershell -ExecutionPolicy Bypass -File api-regression.ps1
powershell -ExecutionPolicy Bypass -File api-regression.ps1 -Base http://localhost:8080 -Password password
```

设计要点：

- 启动先探测 `/api/auth/me` 是否 401，服务未起直接 `exit 1` 并给明确提示

- 中文断言用 UTF-8 HEX 比对，双重编码回潮会立刻被抓到
- 结尾汇总 `TOTAL / PASS / FAIL / SKIP`，有失败退出码为 1，可直接接 CI

## 六、踩坑记录

| 现象 | 根因 | 处理 |
|---|---|---|
| 接口返回 `null` 而非 404 | `ResponseEntity` 不会解包 `Optional` | Service 返回实体，`orElseThrow(404)` |
| PUT 阈值变成空操作 | 删 `if` 时代码把调用一起删了 | 补回调用 + 清未使用 import |
| 农户看到全库告警 / 历史永远为空 | `findAll` 双分支写反两次 | 最终：`seeAll` 走单表，`!seeAll` 走 join + 条件 + `order by` |
| 启动 NPE | `maintainedBy` 用基本类型 `long` 接 NULL | 改包装类型 `Long` |
| 任意请求 500 | 快照 `.get()` 命中已删设备 | 改 `map(...).orElse(false)` |
| 中文全变 `æ¸©åº¦` | 导入时客户端字符集非 utf8mb4，双重编码 | HEX 确认后原地解码，重启应用 |
| `415` 而非 `401` | 测试脚本在无会话分支没传 body | 脚本层修复 |

## 九、面试要点（本阶段沉淀）

1. 功能权限 vs 数据权限：前者管"能不能调"，后者管"能查哪些行"
2. 水平越权防护：条件下推到 SQL，而非查出来再过滤
3. 越权返 404 的取舍：不泄露存在性，代价是排障成本
4. Session vs JWT：内存会话重启掉线，多实例需共享存储
5. `ConcurrentHashMap` 弱一致迭代：无需锁，不抛 CME，但不是精确快照
6. `Map.copyOf` 是防御性拷贝：不可变、遇 null 抛 NPE
7. `Optional.get()` 把"可能没有"退回异常，应 `map(...).orElse(...)`
8. 401 / 403 / 404 / 415 的边界与语义
9. 字符集 vs 排序规则；双重编码用 HEX 判断；MySQL `utf8` 存不了 emoji
10. RBAC 之外必须回答"同角色不同用户的数据怎么隔离"
