## 1. 一句话目标

单机可部署、以配置化扩展新设备类型为目标，为中小型企业解决机房动力环境实时监控问题，实现数据接入、清洗、分析、可视化。

## 2. MVP 边界

### 必须做

- [ ] 多元协议数据接入（MQTT + Modbus）
- [ ] 数据清洗（校验 / 去重 / 补全 / 单位 / 时间）
- [ ] 数据分析（聚合统计 + 滑动窗口趋势）
- [ ] 数据可视化（普通 Web 页面）

### 明确不做

- [ ] 视频监控
- [ ] 3D 数字大屏 / 数字孪生
- [ ] **实时大屏（v2 新增砍掉）**
- [ ] 多企业 / 多租户
- [ ] 短信告警
- [ ] AI 预测型维护
- [ ] 全协议驱动
- [ ] App

## 3. 监控对象 × 数据源清单

| 监控对象 | 数据项 | 接入协议 | 采集频率 | 数据来源 |
|---|---|---|---|---|
| 温湿度传感器 | 温度、湿度 | MQTT | 30-60s | 模拟器 |
| 漏水 | 有无漏水 | MQTT | 事件触发 | 模拟器 |
| 精密空调 | 运行状态 | Modbus | 10-30s | 模拟器 |
| UPS | 电压、电流 | Modbus | 1-5s | 模拟器 |

**关键约束：上报频率 ≠ 存储频率。**

数据到达后逐条实时处理（更新最新值 / 越限判断 / 清洗），入库按 3-5s 采样一次，作为图表数据源。事件型测点（漏水）到达即入库，不走采样节流，因为事件本身稀疏且不可丢。

**采集频率说明：** 表中频率是日常模拟器的运行频率。并发、吞吐、峰值指标统一延后到项目后期、完整验收前压测，日常开发不按 0.1s 压测数据自证。

*注：后续会添加简单单片机提供真实数据。*

## 4. 角色与权限

采用 Session 会话认证，密码 BCrypt 哈希存储，不存明文。

| 操作 | 运维人员 | 决策者 |
|---|---|---|
| 登录、查看实时数据 | ✓ | ✓ |
| 查看历史曲线 | ✓ | ✓ |
| 查看告警列表 | ✓ | ✓ |
| 确认 / 处理告警 | ✓ | ✓ |
| 查看设备在线状态 | ✓ | ✓ |
| 手动重连 / 重采 | ✓ | ✓ |
| 手动清理历史数据 | ✓ | ✓ |
| 新增 / 删除设备 | ✗ | ✓ |
| 新增 / 删除测点 | ✗ | ✓ |
| 修改测点阈值 | ✗ | ✓ |
| 用户管理 | ✗ | 可选，本期不做 |

职责划分：运维人员只负责日常维护（看数据、处理告警、查看在线状态、必要时重连或清理）；决策者负责设备与测点的新增删除、阈值调整。

## 5. 功能需求

### 5.1 数据接入

- MQTT：已实现，EMQX + QoS1 + `cleanSession=false` + 自动重连。
- Modbus：待实现，TCP 方式，用 pymodbus 搭模拟从站。
- 设备与协议通过配置声明，新增 MQTT 类设备只需改配置；新增协议类型通过实现 `ProtocolAdapter` 扩展。

### 5.2 实时流式处理（已修改）

每条消息依次经过：清洗 → 越限判断 → 按策略入库。告警与存储两路订阅共享同一事件流；最新值查询直接读取 `point_value` 最新一条。

### 5.3 数据清洗（五步）

| 步骤 | 内容 |
|---|---|
| 校验 | 类型、范围、空值检查，非法值丢弃并记日志 |
| 去重 | 同设备同测点同采样时间的重复消息只保留一条 |
| 补全 | 缺失字段按约定默认值或上一条有效值补全 |
| 单位 | 统一到约定单位（如温度统一 ℃） |
| 时间 | 设备采样时间缺失时用服务器接收时间兜底 |

清洗结果以质量标记写入存储，便于后续过滤。

### 5.4 存储

- 连续型测点每 3-5s 采样入库一条，内存中始终保持实时最新值（当前实现在内存中尚未保留最新值，列为阶段 3 待办）。
- 事件型测点到达即入库。
- 测点数据保留 ≥ 7 天，定时任务每日清理过期数据。
- 运维人员可手动触发指定时间段的数据清理。

### 5.5 告警

- 越限即产生告警事件，端到端可见延迟 ≤ 3s。
- 状态机：`ACTIVE`（越限中）→ `RECOVERED`（已恢复）。
- 确认不是独立状态：`alarm.confirmed_by` / `alarm.confirmed_at` 为 NULL 表示未确认，有值表示已确认；确认只对 `ACTIVE` 告警生效，已恢复或不存在的告警返回 404。
- 收敛：同一设备同一测点持续越限只保留一条 `ACTIVE` 告警，只更新其当前值；`sample_at` 固定为首次越限时间，`recovered_at - sample_at` 即告警持续时长。
- 恢复：数值回到阈值内时自动标记 `RECOVERED`，`recovered_at` 取首个恢复正常样本的时间。
- 确认：记录确认人与确认时间，可重复确认，后一次覆盖前一次（本期不做确认审计）。

### 5.6 查询与分析

- 最新值查询、按时间区间查询历史。
- 聚合统计：按时间粒度计算 min / max / avg。
- 趋势分析：滑动窗口内的变化趋势判断（上升 / 下降 / 平稳）。

### 5.7 设备与点位管理

- 配置文件只作**首次初始化**：启动时库中不存在该设备/测点则写入，已存在则以库为准，不覆盖。
- 初始化完成后，设备与点位的新增、删除只操作数据库，配置文件不再承担管理职责。
- 删除采用逻辑删除，历史数据保留，避免破坏 7 天数据保留要求。
- 启动时从库加载设备、测点、阈值到内存，供实时处理使用。

### 5.8 设备在线状态

记录每台设备最后一次收到消息的时间。超过约定超时时间未收到数据判定为离线，在设备列表中展示。任一数据源关闭时系统正常降级，不崩溃。

### 5.9 数据可视化（五个页面）

1. 登录页
2. 实时数据页
3. 历史曲线页
4. 告警列表页（含确认按钮）
5. 设备与测点管理页（仅决策者可见写操作）

### 5.10 部署

Docker Compose 一键启动：应用 + MySQL + EMQX + 模拟器。

## 6. 非功能需求

| 项 | 目标值 | 验证阶段 |
|---|---|---|
| 并发接入测点数 | ≥ 100（压测目标 500+） | 后期压测 |
| 数据频率 | 环境类 30-60s、电力类 1-5s、事件类触发 | 后期压测 |
| 吞吐 | 峰值 ≥ 500 条/秒 | 后期压测 |
| 告警时延 | 越限到告警可见 ≤ 3s | 单机实测 |
| 可靠性 | 断线 5s 内自动重连；QoS1 保证不丢；异常数据清洗去重 | 后期实测 |
| 数据保留 | ≥ 7 天 | 定时任务验证 |
| 部署 | 单机 Docker Compose 一键启动 | 交付前 |
| 扩展性 | 新增设备类型以配置为主，尽量不动核心代码 | 新增设备验证 |

## 7. 数据模型

| 表 | 作用 | 关键字段 |
|---|---|---|
| `device` | 设备主数据 | id、device_code（唯一）、name、protocol、connection_config、enabled、last_seen_at |
| `point` | 测点主数据与阈值 | id、device_id、point_code、name、address、time_address、data_type、unit、freq_seconds、min_value、max_value、enabled |
| `point_value` | 采样数据 | id、point_id、value、sample_at、sys_ts、quality |
| `alarm` | 告警记录 | id、point_id、value、threshold、limit_type、status、sample_at、created_at、confirmed_by、confirmed_at、recovered_at、maintained_by |
| `user` | 登录账号与角色 | id、username（唯一）、password_hash、role、enabled |

说明：

- `point_value` 只保存 `point_id`，设备通过 `point.device_id` 关联，不冗余 `device_id`。
- `alarm.sample_at` 为首次越限时间，`alarm.created_at` 为落库时间（服务器时钟），`alarm.value` 为最近一次越限值。
- `alarm.confirmed_by` / `alarm.maintained_by` 外键指向 `user(id)`，删除行为为 RESTRICT，因此用户只能逻辑删除（`user.enabled=0`）。
- `point_value.quality` 为 v2 新增字段（清洗质量标记），当前默认 `OK`，阶段 2 落地后才具备真实区分能力。

## 8. 验收标准

| # | 验收项 | 判定方式 |
|---|---|---|
| 1 | 4 类对象数据在页面正常刷新，延迟 ≤ 3s | 启动模拟器后观察页面 |
| 2 | 注入异常值（如温度超阈值）后 3s 内告警可见 | 构造越限数据 |
| 3 | 图表数据按 3-5s 采样入库，历史曲线可查 | 查库 + 页面曲线 |
| 4 | 断开 MQTT 连接后 5s 内自动重连且不丢数据 | 后期实测 |
| 5 | 关闭任一数据源，系统正常降级、不崩溃 | 停掉模拟器观察 |
| 6 | 新增 1 个设备类型只需改配置、不改核心代码 | 新增一个 MQTT 设备 |
| 7 | 并发、吞吐、采集频率指标达标 | 后期完整验收前压测 |
| 8 | 运维与决策者权限隔离生效 | 两种角色分别登录验证 |
| 9 | 数据保留 7 天，过期自动清理 | 定时任务执行后查库 |
| 10 | Compose 一键启动 | 干净环境验证 |
