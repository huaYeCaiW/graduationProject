*总结*

今日搭建了底层数据框架，所有协议的数据解析后将统一成PointValue.java，目的是平衡比上下游协议差异；解析后数据直人这一种形态，更换设备或数据源类型不影响下游源码处理

- 是什么：所有协议数据解析后统一成 PointValue.java。
- 为什么：抹平上游协议/设备差异，下游只认一种形态。
- 怎么落地：适配层 + 解析层消化差异 → 产出 PointValue。

### LatestValueHolder

~~~java
@Slf4j
@Component
public class LatestValueHolder {

    // 并发安全——Reactor流回调可能多线程，普通HashMap会并发出问题
    private final Map<String, PointValue> latest = new ConcurrentHashMap<>();

    // 拼接key避免不同设备不同测点突
    public void update(PointValue pv) {
        latest.put(pv.getDeviceId() + ":" + pv.getPointId(), pv);
    }

    // RESt API 查询实时值时调
    public Optional<PointValue> get(String deviceId, String pointId) {
        return Optional.ofNullable(latest.get(deviceId + ":" + pointId));
    }
}
~~~

~~~java
@Slf4j
@Component
public class MqttProtocolAdapter implements ProtocolAdapter {

    private final ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(2);
    private final Random random = new Random();

    @Override
    public String protocol() {
        return "mqtt";
    }

    @Override

    @Override
    public void subscribe(DeviceConfig device, Consumer<RawMessage> sink) {
        scheduler.scheduleAtFixedRate(() -> {
            //随机Json

            double hum = 30 + random.nextDouble() *50;      //30~80

            raw.setProtocol("mqtt");
            raw.setPayload(payload);
            raw.setReceivedAt(Instant.now());
            //回调推进
            sink.accept(raw);
            log.debug("模拟报文：{}", payload);
        }, 0, 60, TimeUnit.SECONDS);
    }

    @Override
    public void disconnect(String deviceId) {

    }
}
~~~

### AcquisitionService

*关键功能* ：接入设备

~~~java
@Slf4j
@Service
@RequiredArgsConstructor
public class AcquisitionService implements CommandLineRunner {

    private final DeviceProperties deviceProperties;
    private final List<ProtocolAdapter> adapters;
    private final MessageStream messageStream;

    private Map<String, ProtocolAdapter> adapterMap;

    @Override
    public void run(String... args) throws Exception {
        //适配器注册表
        adapterMap = adapters.stream() .collect(Collectors.toMap(ProtocolAdapter::protocol, Function.identity()));
        //遍历设备
        for (DeviceConfig device : deviceProperties.getDevices()) {
            ProtocolAdapter adapter = adapterMap.get(device.getProtocol());
            if (adapter == null) {
                log.warn("未找到协议适配器: {}", device.getProtocol());
                continue;
            }

            adapter.connect(device);
            adapter.subscribe(device, raw -> messageStream.emit(raw));
            log.info("设备接入完成：id={}，protocol={}", device.getId(), device.getProtocol());
        }
    }
}
~~~

**总结**：机制：Reactor 热流多播（Sinks.Many）

- 是什么：一条 Flux 上挂多个 subscribe，同一份数据**同时**喂给所有订阅者

- 为什么：Cold Stream 每次 subscribe 会让上游重新发射 → 同一条报文 parse 3 次（每个订阅各跑一遍）

- 怎么落地：`Sinks.many().multicast()` 造热流入口，三路订阅共享一条 `valuesFlux`

- Hot vs Cold Stream 的区别、为什么选 Hot 而不是三个 Flux

  *完整链路* 

  AcquisitionService.run()
      → 遍历 devices.yml
      → 找 MqttProtocolAdapter (protocol="mqtt")
      → connect + subscribe(raw -> messageStream.emit(raw))
      → 定时造 RawMessage → sink.accept → messageStream.emit → rawSink.tryEmitNext
      → Reactor 热流：map(parse) → flatMapIterable → Flux<PointValue>
      → 订阅1: LatestValueHolder.update
      → 订阅2: filter(越限) → raiseAlarm → AlarmEvent → AlarmListener → AlarmService.record
      → 订阅3: sample(3s) → PointStore.save

### InMemoryPointStore

*关键功能* ：存储，查

#### save(PointValue value)

~~~java
private final Map<String, List<PointValue>> history = new ConcurrentHashMap<>();
@Override
public void save(PointValue value) {
    //拼key"th-01:temperature"
    String key = value.getDeviceId() + ":" +value.getPointId();
    //如果key不存在，new一个新的；存在返回这个list
    history.computeIfAbsent(key, k -> new CopyOnWriteArrayList<>())
            .add(value);

    log.debug("采样库存：{}", value);
}
~~~

使用Map<>+ConcurrentHashMap<>+CopyOnWriteArrayList<>()防止并发问题

CopyOnWriteArrayList关键使用在读多写少场景，写时复制整组加锁，读时无锁，list值append不中间插入删除，写是复制代价极低，concurrentHashMap的computeIfAbsent是原子的，不会并发丢list

拼key以防混淆设备

#### Optional<PointValue> findLatest(String deviceId, String pointId)

~~~java
@Override
public Optional<PointValue> findLatest(String deviceId, String pointId) {
    //拼key
    String key = deviceId + ":" + pointId;
    List<PointValue> list = history.get(key);
    return list == null || list.isEmpty() ? Optional.empty() : Optional.of(list.getLast());
}
~~~

#### List<PointValue> findByRange(String deviceId, String pointId, Instant startTime, Instant endTime)

~~~java
//查某时间范围内值
    @Override
    public List<PointValue> findByRange(String deviceId, String pointId, Instant startTime, Instant endTime) {

        //拼key"th-01:temperature"
        String key = deviceId + ":" + pointId;
        //取数组
        List<PointValue> list = history.get(key);
        if (list == null) {
            return Collections.emptyList();
        }
        return list.stream()
                .filter(pv -> !pv.getTimestamp().isBefore(startTime)
                                     && !pv.getTimestamp().isAfter(endTime))
                .toList();
    }
~~~

!pv.getTimestamp().isBefore(startTime)取反是为了< 变 >= 开区间转为闭区间

关键代码：history.computeIfAbsent(key, k -> new CopyOnWriteArrayList<>())

含义：查是否有相同key的list没有就新建一个CopyOnWriteArrayList()，返回值list。save()需写操作，所以需要computeIfAbsent，其他两个方法只读在没有这个key时返回empty就行不需要创建

#### connect(DeviceConfig device) 

~~~java
@Override
public void connect(DeviceConfig device) {
    try {
        // 新建paho客户端clientId全局唯一
        String clientId = "donghuan_java_" + device.getId() +"_" + System.currentTimeMillis();
        this.client = new MqttClient(broker,clientId);

        // 没回调
        this.client.setCallback(new MqttCallback() {
            //自动重连
            @Override
            public void connectionLost(Throwable cause) {
                log.warn("MQTT断开连接，paho自动重连：{}", cause.getMessage());
            }

            // 回调签名
            @Override
            public void messageArrived(String topic, MqttMessage message) throws Exception {
                String payload = new String(message.getPayload());
                log.debug("收到MQTT：topic={}，payload={}", topic, payload);

                //组装raw
                RawMessage raw = new RawMessage();
              	raw.setDeviceId(device.getId());
                raw.setProtocol("mqtt");
                raw.setTopic(topic);
                raw.setPayload(payload);
                raw.setReceivedAt(Instant.now());

                messageStream.emit(raw);
            }

            @Override
            public void deliveryComplete(IMqttDeliveryToken token) {

            }
        });

        // 连接选项
        MqttConnectOptions options = new MqttConnectOptions();
        options.setAutomaticReconnect(true);
        options.setCleanSession(false);
        options.setConnectionTimeout(10);
        options.setKeepAliveInterval(60);

        // 连broker
        this.client.connect(options);

        // 订阅topic
        this.client.subscribe(device.getConnection().getTopic, 1);

        log.info("√ MQTT连接成功：broker={}，topic={}，deviceId={}", broker, device.getConnection().getTopic(), device.getId());
    } catch (MqttException e) {
        log.error("× MQTT连接失败：{}", e.getMessage());
    }
}
~~~

### 核心落地逻辑

   验证：latest接口能取到最后一条，range能按时间过滤

   问题：要不要写DeviceService/PointQueryService？
